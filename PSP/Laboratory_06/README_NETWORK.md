# Laboratory 06 — Named Pipe между двумя ПК

## Что исправлено

- В ClientNP был фиксированный DESKTOP-1ESRE1C, в ClientNPt/ClientNPct — только свой ПК (`.`). Теперь у всех клиентов адрес сервера передаётся первым аргументом. Без аргумента остаётся локальный тест.
- `CreateNamedPipe(..., NULL)` использовал DACL по умолчанию: другому пользователю обычно доступно чтение, но клиент запрашивает и запись. Теперь сервер явно разрешает чтение/запись **аутентифицированным пользователям Windows** (AU), не анонимам и не гостям. Это учебный доступ для доверенной сети; SMB-аутентификацию он не отменяет. В рабочем приложении круг пользователей следует сузить до конкретной учётной записи/группы.
- Убран выход за границу `readBuf[512]` при приёме ровно 512 байт; `ERROR_MORE_DATA` дочитывается до конца сообщения (учебный предел — 64 КиБ). Клиенты используют режим сообщений.
- Сервер принимает последующих клиентов без перезапуска, клиенты с CreateFile ждут занятый экземпляр до 10 с; CallNamedPipe тоже получил конечное ожидание. Это ожидание **свободного экземпляра**, не общий тайм-аут сетевого подключения или ответа.
- Ошибки теперь содержат настоящий код и описание Windows, подсказки по SMB; при ошибке клиенты возвращают код 1. `system("pause")` убран: запускайте программы из терминала.
- Общие функции вынесены в `ServerNP/PipeCommon.h`, краткие комментарии оставлены у исправлений. Добавлены `/utf-8`, сборка и воспроизводимые тесты.

## Сборка и запуск

В Visual Studio откройте `ServerNP/ServerNP.slnx` и пересоберите **все четыре проекта**. В свойствах клиента → Отладка → Аргументы команды укажите имя/IPv4 компьютера с ServerNP.

Или из PowerShell в этой папке:

```powershell
.\build.ps1 -WithTests
.\bin\ServerNP.exe
```

На втором ПК в терминале (пример IPv4 замените адресом сервера):

```powershell
.\ClientNP.exe 192.168.1.10
.\ClientNPt.exe 192.168.1.10
.\ClientNPct.exe 192.168.1.10
```

Клиенты запускаются по очереди; сервер не надо перезапускать. Для проверки на одном ПК используйте `.` вместо адреса. Нужна **пара сервер–клиент**, а не два клиента. Ответ сервера, как и раньше, фиксированный: «Сообщение получено!». Это не чат между двумя клиентами и не общая память двух компьютеров.

Если однокурсник использует собственный код, согласуйте имя канала `Tube`, режим сообщений и кодировку текста: исправленные программы передают UTF-8. CP1251 на другой стороне даст нечитаемую кириллицу, хотя сами байты будут переданы.

## Что проверить на двух компьютерах

1. Выберите сервер. На нём выполните `hostname` и `ipconfig`: нужен IPv4 адаптера вашей общей сети, не VPN/Radmin/VirtualBox. Если меняетесь ролями, все следующие серверные настройки нужны уже на другом ПК.
2. Только для своей доверенной сети установите профиль **Частная** и включите «Общий доступ к файлам и принтерам». Named Pipe по сети использует **SMB через TCP 445**, а не только сетевое обнаружение. Не открывайте этот порт в интернет.
3. На сервере должна работать служба `LanmanServer` («Сервер»), на клиенте — `LanmanWorkstation` («Рабочая станция»). В брандмауэре сервера разрешите входящий SMB-In / TCP 445 для частного профиля, желательно только с IPv4 однокурсника. Антивирус/сторонний firewall тоже могут фильтровать SMB. Полностью отключать брандмауэр не нужно.
4. С клиента проверьте порт, ещё до запуска клиента лабораторной:

   ```powershell
   Test-NetConnection 192.168.1.10 -Port 445
   ```

   Нужно `TcpTestSucceeded : True`. Если False, код лабораторной ещё не участвует: проверьте IPv4, правила, службы и изоляцию устройств/AP isolation/гостевую Wi-Fi сеть. Успешный ping не доказывает доступность SMB.
5. Windows должна аутентифицировать клиента на сервере. Для двух домашних ПК без домена удобно использовать **обычную локальную учётную запись сервера с непустым паролем**. Нельзя вместо пароля передавать PIN Windows Hello. Не требуется делать эту запись администратором. С клиента:

   ```powershell
   net use \\192.168.1.10\IPC$ /user:ИМЯ_ПК_СЕРВЕРА\ИМЯ_ПОЛЬЗОВАТЕЛЯ *
   ```

   `*` запрашивает пароль интерактивно, не сохраняйте его в исходниках. Используйте тот же адрес (`192.168.1.10`) и в командах клиента. Запустите клиент из того же обычного терминала/сеанса, где выполнен `net use`: повышенный сеанс Visual Studio может иметь другие SMB-подключения.
6. После успешного входа сначала запустите ServerNP на сервере, затем один из клиентов с его адресом. Создавать общую папку и менять `\\.\pipe\Tube` в сервере не нужно: сервер создаёт канал на своём ПК, а клиент обращается к нему по `\\СЕРВЕР\pipe\Tube`.

Не включайте SMB1, анонимный доступ/AllowInsecureGuestAuth и не отключайте SMB signing для обхода ошибки. Современные Windows работают с SMB2/3 и нормальной аутентификацией.

## Если всё ещё ошибка

| Код | Что проверять |
| --- | --- |
| 2/3 | Запущен ли ServerNP на **указанном** ПК, совпадает ли Tube |
| 5 | Права на канал **или** отказ SMB/политики входа; сначала проверить `net use` |
| 53/67 | Адрес/имя, доступность TCP 445, службу Сервер |
| 1219 | Уже есть SMB-сеанс к этому адресу с другими реквизитами; посмотреть `net use`, закрыть только нужное подключение, не удалять все сеансы |
| 1326 | Неверные имя/пароль; нужна учётная запись сервера, не клиента и не PIN |
| 1385 | Учётной записи запрещён сетевой вход локальной/доменной политикой |
| 231/121 | Занятый экземпляр/истекло ожидание; дождаться завершения другого клиента |

Сохраните точное сообщение ошибки, вывод `Test-NetConnection` и результат `net use` **без пароля**. Без них нельзя гарантировать исправность чужого компьютера и сети.

## Проверки кода

```powershell
.\build.ps1 -WithTests
.\tests\Test-NamedPipes.ps1 -IncludeSmbLoopback
```

Скрипт запускает/останавливает только собственный сервер; проверяет три API, повторные подключения, ожидание занятого канала, запрет второго сервера, ошибки при отсутствии сервера, адресацию, DACL, сообщения 1/511/512/513/1536/65536 байт и дочитывание ответа 1537 байт. С ключом проверяются также UNC-подключения к имени **этого** компьютера. Логи — `test-results/`. Проверка с другим ПК и другой учётной записью всё равно обязательна.
