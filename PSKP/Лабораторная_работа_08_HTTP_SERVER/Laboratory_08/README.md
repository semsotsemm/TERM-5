# Лабораторная работа 08. HTTP-сервер

Работа проверена на Node.js 24. Из папки лабораторной выполни

```powershell
npm ci
npm start
```

Открыть [127.0.0.1:5000](http://127.0.0.1:5000). Для запросов с телом импортировать `08-00.postman_collection.json` в Postman и запустить коллекцию.

## Проверка в браузере

- `/formparameter` — заполнить поля и нажать одну из кнопок. В ответе `action` содержит значение нажатой кнопки.
- `/files/example.txt` — открыть пример файла. `/files/missing.txt` должен вернуть 404.
- `/upload` — выбрать текстовый файл с новым именем и отправить. Проверить файл по адресу `/files/имя_файла` и счётчик в `/files`.
- `/close` — выполнить последним. Сервер остановится через 10 секунд.

## Влияние KeepAliveTimeout

Изменить тайм-аут, затем выполнить два запроса по одному HTTP-соединению с паузой между ними:

```powershell
curl.exe "http://127.0.0.1:5000/connection?set=3000"
curl.exe -v --rate 1/1s "http://127.0.0.1:5000/socket" "http://127.0.0.1:5000/socket"
curl.exe "http://127.0.0.1:5000/connection?set=300"
curl.exe -v --rate 1/1s "http://127.0.0.1:5000/socket" "http://127.0.0.1:5000/socket"
```

При 3000 мс клиент успевает повторно использовать соединение. При 300 мс пауза в одну секунду превышает тайм-аут, и второй запрос открывает новое соединение. Это видно по порту клиента в выводе `/socket`.

## Заголовки в /headers

| Заголовок | Назначение |
| --- | --- |
| Host | Адрес и, при необходимости, порт сервера, к которому обращается клиент. |
| Connection | Управление текущим соединением. Значение `close` указывает, что соединение закроется после ответа. |
| User-Agent | Сведения о клиентской программе. |
| Accept | Типы содержимого, которые клиент готов принять. |
| Accept-Encoding | Поддерживаемые способы сжатия ответа. |
| Accept-Language | Предпочитаемые языки ответа. |
| Cache-Control, Pragma | Указания по использованию кэша. |
| Referer | Адрес страницы, с которой выполнен переход. |
| Sec-CH-UA, Sec-CH-UA-Mobile, Sec-CH-UA-Platform | Сведения браузера о его семействе, мобильном режиме и платформе. |
| Sec-Fetch-Site, Sec-Fetch-Mode, Sec-Fetch-User, Sec-Fetch-Dest | Контекст запроса: отношение между источниками, режим, действие пользователя и назначение ресурса. |
| Upgrade-Insecure-Requests | Предпочтение клиента использовать защищённое соединение, когда это возможно. |
| Postman-Token | Уникальное значение, которое Postman может добавлять к запросам. |
| Content-Type | Формат содержимого сообщения. Для ответа `/headers` это текст в UTF-8. |
| Date | Время формирования ответа сервера в UTC. |
| X-Lab-Number | Пользовательский заголовок ответа с номером лабораторной работы. |

## Задание 15

40. **Content-Type** указывает формат содержимого запроса или ответа. Дополнительные параметры могут задавать кодировку текста или границу частей сообщения.
41. **Accept** сообщает серверу, какие типы содержимого клиент готов принять.
42. **multipart/form-data** передаёт поля формы отдельными частями. Так можно отправлять текстовые поля и файлы в одном запросе.
43. У формы задают атрибуты `method="post"` и `enctype="multipart/form-data"`. Браузер сам формирует заголовок с границей частей.
44. У формы с методом POST кодировка по умолчанию — `application/x-www-form-urlencoded`.
45. При GET-отправке формы браузер помещает параметры после `?` в URL. Пары `имя=значение` разделяются `&`, а специальные символы кодируются. Маршрут также может передавать значения в сегментах пути, как в `/parameter/12/3`.
46. При POST-отправке формы данные помещаются в тело запроса. Формат зависит от `enctype`. При запросе из программы в теле можно передать JSON, XML и другие данные с соответствующим `Content-Type`.
47. **JSON** — текстовый формат обмена данными. Он описывает объекты, массивы, строки, числа, логические значения и `null`.
48. **XML** — язык разметки для структурированных данных. Документ состоит из элементов, у которых могут быть атрибуты, текст и вложенные элементы.
