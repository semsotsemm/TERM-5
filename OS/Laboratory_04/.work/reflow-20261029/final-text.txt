Введение
Цель работы — получение практических навыков создания потоков и
управления их выполнением в операционных системах Windows и Linux.
Рассматриваются ожидание завершения потоков, приостановка и
возобновление выполнения, локальное хранение данных и кооперативное
переключение вычислительных контекстов.
В Windows подготовлены приложения Lab-04a, Lab-04b, Lab-04c и Lab-
04d, варианты поиска простых чисел Lab-04e, Lab-04p и Lab-04p2, а также
приложение Lab-04pi. В Linux подготовлены Lab-04px, Lab-04p_Linux и Lab-
04pi_Linux. Общая функция Lab_04x выводит идентификаторы процесса и
потока, номер итерации и циклически выбранные символы имени
пользователя и ФИО.
Для достижения цели работы решаются следующие задачи:
– создание двух дочерних потоков и ожидание их завершения главным
потоком;
– наблюдение за потоками средствами PowerShell, Process Explorer, ps и
файловой системы /proc;
– исследование изменения состояния потоков при приостановке,
возобновлении и принудительном завершении;
– поиск простых чисел с использованием TLS и анализ совместной
записи в общий массив;
– сравнение времени выполнения при различном числе
вычислительных потоков;
– вычисление приближения числа π с помощью волокон и
пользовательских контекстов.
Результаты работы приложений представляются снимками консоли и
средствами мониторинга. Отдельно фиксируются показатели
производительности, корректность полученных данных и освобождение
ресурсов на штатном пути выполнения.

1 Теоретические основы управления потоками
1.1 Потоки и ожидание завершения
Поток представляет собой последовательность выполнения команд
внутри процесса. Потоки одного процесса используют общее адресное
пространство, но имеют собственный стек и контекст выполнения. Поэтому
одинаковый PID при различных TID соответствует нескольким потокам
одного процесса. Планировщик может чередовать их выполнение или
распределять потоки по различным ядрам.
В Windows поток создаётся функцией CreateThread. Дескриптор потока
позволяет ожидать его завершения и управлять выполнением. В Linux
соответствующие операции выполняются с помощью pthread_create и
pthread_join. Ожидание завершения требуется перед освобождением данных,
переданных работающим потокам.
1.2 Локальное хранение данных потока
Thread Local Storage обеспечивает отдельное значение переменной или
указателя для каждого потока. В Windows динамический TLS использует
TlsAlloc, TlsSetValue, TlsGetValue и TlsFree [1]. Вариант __declspec(thread)
задаёт потоковую область хранения при объявлении переменной. В Linux
применяются ключи pthread_key_t и модификатор __thread.
TLS разделяет промежуточные данные, но не защищает общий массив
и общий индекс записи. Если несколько потоков изменяют один счётчик без
синхронизации, результат зависит от порядка выполнения операций.
Сортировка после ожидания потоков не восстанавливает значения,
потерянные при записи.
1.3 Волокна и пользовательские контексты
Волокна переключаются по инициативе программы. В Windows для
этого используются ConvertThreadToFiber, CreateFiber и SwitchToFiber [4]. В
реализации Linux контекст задаётся структурой ucontext_t, а переключение
выполняется swapcontext [8]. Несколько волокон внутри одного потока не
обеспечивают одновременное вычисление на нескольких ядрах.
Кооперативное выполнение позволяет делить длительную работу на
небольшие порции. Размер порции определяет частоту переключений, а
проверка условия завершения позволяет остановить вычисление до
окончания очередной порции.

2 Реализация приложений Windows
2.1 Функция Lab_04x
Функция Lab_04x получает количество итераций через аргумент. Для
имени пользователя и ФИО выделяются массивы wchar_t. В них записаны
строки «User-3af11550» и «Антипов Алексей Романович». Выбор символов
выполняется по остатку от деления номера итерации на длину
соответствующей строки.
PID и TID определяются функциями GetCurrentProcessId и
GetCurrentThreadId. Вывод организован через wprintf из семейства
форматированного вывода printf. Формат строки содержит PID, TID, номер
итерации, символ имени пользователя и символ ФИО. Задержка Sleep
изменяется от 350 до 450 мс.
Строки имени пользователя и ФИО обрабатываются раздельно. Для
каждой используется собственная длина, поэтому возврат к началу одной
строки не изменяет положение в другой. Остаток от деления индекса на
длину строки ограничивает выбор её допустимыми позициями. Повторение
символов в выводе связано с циклическим обходом строк, а не с повторным
запуском функции.
Идентификатор процесса указывает, какому процессу принадлежит
выполняемый код, а идентификатор потока различает последовательности
выполнения внутри него. В однопоточном контрольном запуске оба значения
сохраняются во всех строках. При использовании той же функции
несколькими потоками PID остаётся общим, а TID позволяет восстановить
вывод каждого рабочего цикла независимо от взаимного порядка строк.
Задержка между итерациями делает изменение вывода наблюдаемым в
консоли. Её продолжительность не определяет порядок выполнения
остальных потоков и не используется как средство синхронизации. Число
повторений задаётся аргументом функции, поэтому проверка цикла
выполняется по последнему номеру итерации и количеству выведенных
строк, а не по времени работы программы.

освобождение принадлежащих программе ресурсов. Эти события происходят
в разных местах программы и не должны считаться одним действием.

2.7 Параметризованный поиск в Lab 04p

ожидает завершения всех рабочих потоков, проверяет их коды завершения,
сортирует сохранённые значения и выводит результат.

2.8 Статический TLS в Lab 04p2

5.2 Локальное хранение в Lab 04p Linux
Для поиска простых чисел подготовлены два приложения: Lab-
04p_Linux с динамическим TLS и Lab-04p2_Linux со статическим TLS. Оба
приложения получают количество потоков и границы диапазона через
аргументы командной строки. Диапазон разделяется между потоками на
части, размеры которых отличаются не более чем на единицу.
В Lab-04p_Linux ключ TLS создаётся функцией pthread_key_create
через pthread_once. Каждый поток выделяет структуру LocalData,
содержащую указатель на промежуточный буфер и счётчик найденных
чисел. Структура связывается с ключом через pthread_setspecific, а доступ к
ней выполняется через pthread_getspecific. При завершении потока
деструктор destroy_tls освобождает буфер и структуру. После ожидания всех
потоков главный поток удаляет ключ.
В Lab-04p2_Linux указатель localBuffer и счётчик localCount объявлены
с модификатором __thread, поэтому каждый поток имеет собственные
экземпляры этих переменных. Буфер выделяется динамически и
освобождается перед возвратом из потоковой функции.
В обоих вариантах найденные числа переносятся в общий массив без
синхронизации. Между записью элемента и обновлением общего индекса
предусмотрена задержка usleep(1000), повышающая вероятность проявления
потери данных. После ожидания созданных потоков главный поток
сортирует общий массив и выводит количество сохранённых чисел и сами
значения.

5.3 Вычисление π через пользовательские контексты
В Lab-04pi_Linux волокна реализованы с помощью ucontext_t. Для
каждого рабочего контекста вызывается getcontext, выделяется стек размером
64 КБ и назначается функция fiber_func через makecontext. В поле uc_link
записан указатель на main_ctx. Главный цикл выбирает current_fiber и
переключается к нему через swapcontext [8].
Рабочий контекст обрабатывает очередной блок из 5000 членов ряда
Лейбница по формуле (4.1). Частичная сумма добавляется к total_pi, затем
выполняется обратное переключение к main_ctx. Несколько контекстов
последовательно используют один поток операционной системы.
Для SIGINT установлен обработчик sigaction. Он изменяет только
keep_running, объявленный volatile sig_atomic_t. Печать результата и
освобождение памяти выполняются после выхода из вычислительного цикла.
На штатном пути освобождаются стеки всех контекстов, массив stacks и
массив fiber_ctxs.
Программа запущена командой ./Lab-04pi_Linux 4 с четырьмя
рабочими контекстами. После нажатия Ctrl+C получено приближение π =

несинхронизированной записи в общий массив. Независимость локальных
буферов не защищает общий индекс записи, а последующая сортировка не
восстанавливает потерянные значения.
Для сравнения производительности подготовлены отдельные
benchmark-версии без искусственных задержек. В Windows и Linux
выполнены серии измерений при количестве исполнителей 1, 2, 4, 8 и 16.
Результаты проверялись сравнением полного отсортированного списка с

результат, поэтому их время нельзя рассматривать как гарантированное
ускорение корректного вычисления. Увеличение количества исполнителей не
во всех случаях уменьшало время выполнения.
Вычисление π выполнено с использованием волокон Windows и
пользовательских контекстов Linux. Проверена остановка по Ctrl+C с
выводом накопленного приближения. В отдельных экспериментах
сопоставлены размеры блока 1000, 2000, 4000 и 5000 членов ряда. В обеих
системах наибольшая медианная производительность в проведённых сериях

Этот результат относится к исследованным условиям и не устанавливает

struct LocalData {

};

pthread_key_t tlsKey;

void destroy_tls(void* pointer) {
LocalData* data = static_cast<LocalData*>(pointer);
if (data) {
free(data->buffer);
free(data);
}
}
void init_tls() {
tls_error = pthread_key_create(&tlsKey, destroy_tls);
}

void WINAPI FiberFunc(LPVOID lpParameter) {
while (keep_running.load(std::memory_order_relaxed)) {
long long start = current_n;
current_n += CHUNK_SIZE;
double partial_sum = 0.0;
for (long long i = start; i < start + CHUNK_SIZE; i++) {
if (!keep_running.load(std::memory_order_relaxed)) break;
double term = 1.0 / (2.0 * i + 1.0);
if (i % 2 != 0) {
term = -term;
}
partial_sum += term;
}
total_pi += partial_sum;
SwitchToFiber(main_fiber);
}
SwitchToFiber(main_fiber);
}
