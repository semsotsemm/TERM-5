[64]  Reportunnumbered Введение
[65]   Цель работы — получение практических навыков создания потоков и управления их выполнением в операционных системах Windows и Linux. Рассматриваются ожидание завершения потоков, приостановка и возобновление выполнения, локальное хранение данных и кооперативное переключение вычислительных контекстов.
[66]   В Windows подготовлены приложения Lab-04a, Lab-04b, Lab-04c и Lab-04d, варианты поиска простых чисел Lab-04e, Lab-04p и Lab-04p2, а также приложение Lab-04pi. В Linux подготовлены Lab-04px, Lab-04p_Linux и Lab-04pi_Linux. Общая функция Lab_04x выводит идентификаторы процесса и потока, номер итерации и циклически выбранные символы имени пользователя и ФИО.
[67]   Для достижения цели работы решаются следующие задачи:
[68]   – создание двух дочерних потоков и ожидание их завершения главным потоком;
[69]   – наблюдение за потоками средствами PowerShell, Process Explorer, ps и файловой системы /proc;
[70]   – исследование изменения состояния потоков при приостановке, возобновлении и принудительном завершении;
[71]   – поиск простых чисел с использованием TLS и анализ совместной записи в общий массив;
[72]   – сравнение времени выполнения при различном числе вычислительных потоков;
[73]   – вычисление приближения числа π с помощью волокон и пользовательских контекстов.
[74]   Результаты работы приложений представляются снимками консоли и средствами мониторинга. Отдельно фиксируются показатели производительности, корректность полученных данных и освобождение ресурсов на штатном пути выполнения.
[75]  1 Теоретические основы управления потоками
[76]  2 Потоки и ожидание завершения
[77]   Поток представляет собой последовательность выполнения команд внутри процесса. Потоки одного процесса используют общее адресное пространство, но имеют собственный стек и контекст выполнения. Поэтому одинаковый PID при различных TID соответствует нескольким потокам одного процесса. Планировщик может чередовать их выполнение или распределять потоки по различным ядрам.
[78]   В Windows поток создаётся функцией CreateThread. Дескриптор потока позволяет ожидать его завершения и управлять выполнением. В Linux соответствующие операции выполняются с помощью pthread_create и pthread_join. Ожидание завершения требуется перед освобождением данных, переданных работающим потокам.
[79]  2 Локальное хранение данных потока
[80]   Thread Local Storage обеспечивает отдельное значение переменной или указателя для каждого потока. В Windows динамический TLS использует TlsAlloc, TlsSetValue, TlsGetValue и TlsFree [1]. Вариант __declspec(thread) задаёт потоковую область хранения при объявлении переменной. В Linux применяются ключи pthread_key_t и модификатор __thread.
[81]   TLS разделяет промежуточные данные, но не защищает общий массив и общий индекс записи. Если несколько потоков изменяют один счётчик без синхронизации, результат зависит от порядка выполнения операций. Сортировка после ожидания потоков не восстанавливает значения, потерянные при записи.
[82]  2 Волокна и пользовательские контексты
[83]   Волокна переключаются по инициативе программы. В Windows для этого используются ConvertThreadToFiber, CreateFiber и SwitchToFiber [4]. В реализации Linux контекст задаётся структурой ucontext_t, а переключение выполняется swapcontext [8]. Несколько волокон внутри одного потока не обеспечивают одновременное вычисление на нескольких ядрах.
[84]   Кооперативное выполнение позволяет делить длительную работу на небольшие порции. Размер порции определяет частоту переключений, а проверка условия завершения позволяет остановить вычисление до окончания очередной порции.

[142]  2 Поиск простых чисел и WinAPI TLS
[143]   Функция L4Primes реализована в приложении Lab-04e. Число проверяется перебором возможных делителей от 2 до квадратного корня. Значения не больше 1 исключаются. Для промежуточных результатов каждого потока выделяется отдельный массив, указатель на который записывается в TLS через TlsSetValue.
[144]   Общий индекс TLS создаётся TlsAlloc. Для получения локального указателя используется TlsGetValue. После расчёта поток переносит значения из локального буфера в globalPrimes и освобождает буфер. Главный поток после ожидания закрывает дескрипторы и освобождает TLS-индекс [1].
[145]   В Lab-04e поиск выполняется тремя потоками на диапазонах [2;3000], [3001;6000] и [6001;9000]. После завершения потоков приложение выводит значение общего счётчика globalIndex. Результат запуска представлен на рисунке 2.12.
[146] IMAGE[12]  Рисунок 2.12 – Результат приложения Lab 04e с TLS
[147]   В диапазоне [2;9000] содержится 669простых числа. На рисунке 2.12 значение globalIndex равно 669, что подтверждает результат.
[148]   TLS обеспечивает отдельный промежуточный буфер для каждого потока, но не синхронизирует запись в globalPrimes и изменение globalIndex. Несколько потоков могут использовать одну позицию массива и перезаписывать результаты друг друга. Задержка Sleep(1) между чтением старого значения индекса и его обновлением увеличивает вероятность проявления гонки данных.
[149]  2 Параметризованный поиск в Lab 04p
[150]   Приложение Lab-04p получает три аргумента: число потоков, нижнюю и верхнюю границы диапазона. Диапазон делится на непересекающиеся части. Остаток от деления распределяется по одному дополнительному элементу между первыми потоками. Главный поток ожидает завершения всех созданных потоков, затем сортирует полученные данные функцией qsort.
[151]   Каждый рабочий поток вызывает L4Primes для своей части диапазона. Указатель на промежуточный буфер сохраняется через TlsSetValue и получается через TlsGetValue. После поиска поток переносит найденные числа в globalPrimes без синхронизации общего индекса. Главный поток ожидает завершения всех рабочих потоков, проверяет их коды завершения, сортирует сохранённые значения и выводит результат.

[155]  2 2.8 Статический TLS в Lab 04p2
[156]   В Lab-04p2 указатель localBuffer и счётчик localCount объявлены с модификатором __declspec(thread). Каждый поток выделяет локальный массив, сохраняет в него простые числа своего диапазона и после завершения поиска переносит значения в общий массив. [157]   Число потоков и границы диапазона передаются через аргументы командной строки. Главный поток ожидает завершения всех рабочих потоков и проверяет их коды завершения. Время измеряется функцией QueryPerformanceCounter от начала создания потоков до окончания ожидания и проверки кодов завершения. Сортировка, вывод чисел и освобождение ресурсов в измеренное время не входят.

[215]  a Для поиска простых чисел подготовлены два приложения: Lab-04p_Linux с динамическим TLS и Lab-04p2_Linux со статическим TLS.
