# ЛР5 — Windows

Открой `Laboratory_05.slnx` в Visual Studio 2026. Выбери `x64`, конфигурацию `Debug` или `Release`, затем назначь нужный проект запускаемым и нажми Ctrl+F5. Для проектов с параметрами они задаются в свойствах проекта: «Отладка → Аргументы команды».

У каждого приложения есть собственный cpp-файл. Общие функции ОС находятся в `common/Lab05.hpp`, модели — в `common/Scheduler.cpp`, их интерфейс — в `common/Scheduler.hpp`. Все восемь приложений написаны на C++17, Python для запуска не нужен.

Можно собрать весь комплект из обычной консоли:

```bat
build.cmd
cd bin\x64\Release
Lab-05a.exe
Lab-05x.exe 10000 1
```

В выводе `Lab-05a` найди `MASK_DEC` и `ONE_CPU_MASK_DEC`. Вместо `255` и `1` в следующих примерах используй эти значения, если они отличаются на твоём компьютере. Полная нагрузка — `1000000 200` (около 200 секунд); для быстрой проверки — `10000 1`.

```bat
Lab-05b.exe 255 32 32 1000000 200
Lab-05b.exe 255 16384 128 1000000 200
Lab-05b.exe 1 16384 128 1000000 200
Lab-05c.exe 255 32 0 0 1000000 200
Lab-05c.exe 255 32 -2 2 1000000 200
Lab-05c.exe 1 32 -2 2 1000000 200
```

У `Lab-05b` создаются отдельные консоли дочерних процессов. После `FINISHED` закрой каждую нажатием Enter: родитель ожидает их завершения. Строка `FIRST_FINISH` фиксирует прогресс один раз; для потоков ожидаются одинаковый PID и разные TID. Не подставляй PID/TID из отчёта — они меняются при каждом запуске.

Модели запускаются быстро и не создают реальные планируемые задачи:

```bat
Lab-05SJF.exe
Lab-05RR.exe --quantum 80
Lab-05CP.exe --quantum 80
Lab-05RR.exe --compare
Lab-05MQ.exe --seed 525
Lab-05MQ.exe --seed 525 --summary
```

`--compare` проверяет кванты 5, 10, 20, 40 и 80 для RR и CP. В этом наборе ожидаются `BEST_RR_QUANTUM=80`, `BEST_CP_QUANTUM=80`; среднее ожидание SJF — 154, RR(80) — 207,5, CP(80) — 170,5. Для MQ seed=525: 100 процессов, 397 перемещений, 2047 переключений, makespan=28957. По умолчанию MQ печатает все 100 процессов для каждой очереди; `--summary` сокращает консольный вывод. Полные таблицы сохраняются в обоих режимах.

Для входного CSV и каталога результатов можно задать `--tasks путь\tasks.csv` и `--out путь\results`. Исходный `tasks.csv` копируется к exe при сборке. Каталог `reference-results` содержит результаты первоначальных опытов для сверки; новые выгрузки создаются в `results` относительно рабочей папки.

Поддерживается и CMake: `cmake -S . -B build`, затем `cmake --build build --config Release`.
