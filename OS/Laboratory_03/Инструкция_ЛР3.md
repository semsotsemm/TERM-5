# Лабораторная работа 3 Управление процессами

Это инструкция к заданию `ОС ЛР3.docx` и исправленному отчёту `Отчет_ЛР3_исправленный.docx`. В папке `Lab03_sources` находятся **полные исходники** всех программ; листинги в приложениях отчёта показывают только ключевые фрагменты. Сначала выполните Windows-часть в виртуальной машине Windows, затем Linux-часть в Ubuntu. LFS для этой лабораторной не требуется: задание требует Linux/POSIX, и Ubuntu подходит.

Пути ниже относятся к **гостевым** системам. Скопируйте папку `Lab03_sources/Windows` в Windows-ВМ, например в `%USERPROFILE%\Desktop\Lab03`, а `Lab03_sources/Linux` в Ubuntu, например в `~/lab03`. Способ передачи (общая папка ВМ, drag-and-drop, флеш-образ) зависит от настроек виртуальной машины; проверьте, что после копирования видны все перечисленные ниже файлы. Не запускайте команды Linux в cmd и наоборот.

## 2. Windows Подготовка и компиляция

Откройте **x64 Native Tools Command Prompt** установленной Visual Studio или Build Tools. Обычная cmd может не знать команду `cl`. Если `cl` отсутствует даже в Developer Command Prompt, установите компонент **Desktop development with C++** через Visual Studio Installer и откройте новый x64 Native Tools Command Prompt. Официальная инструкция Microsoft: <https://learn.microsoft.com/en-us/cpp/build/building-on-the-command-line>.

Введите в этом окне:

```bat
where cl
cd /d "%USERPROFILE%\Desktop\Lab03"
dir
cl /nologo /EHsc /std:c++17 /W4 /Fe:Lab-03x.exe Lab-03x.cpp
cl /nologo /EHsc /std:c++17 /W4 /Fe:Lab-03a.exe Lab-03a.cpp
cl /nologo /EHsc /std:c++17 /W4 /Fe:Lab-03b.exe Lab-03b.cpp
cl /nologo /EHsc /std:c++17 /W4 /Fe:Lab-03c.exe Lab-03c.cpp
cl /nologo /EHsc /std:c++17 /W4 /Fe:Lab-03d-client.exe Lab-03d-client.cpp
cl /nologo /EHsc /std:c++17 /W4 /Fe:Lab-03d-server.exe Lab-03d-server.cpp
cl /nologo /EHsc /std:c++17 /W4 /Fe:Lab-03-startup-child.exe Lab-03-startup-child.cpp
cl /nologo /EHsc /std:c++17 /W4 /Fe:Lab-03-startup-parent.exe Lab-03-startup-parent.cpp
dir *.exe
```

Если папка скопирована не на рабочий стол, замените только путь в `cd /d`. После компиляции все восемь `.exe` должны находиться рядом. Если MSVC пишет, что не найден `win_launch.hpp`, заголовок скопирован не туда.

### 2.1 Lab-03x Аргумент, ITER_NUM и ошибочный запуск

В том же **cmd**:

```bat
Lab-03x.exe 5
set ITER_NUM=4
Lab-03x.exe
Lab-03x.exe 2
set ITER_NUM=
Lab-03x.exe
echo %errorlevel%
```

Ожидается 5, затем 4, затем 2 итерации: аргумент командной строки имеет приоритет перед переменной. Последний запуск завершается ошибкой. В cmd код `0xC0000005` может отображаться как десятичное `-1073741819` или `3221225477`; это одно и то же 32-битное значение. **Скриншот 2.1**: захватите все три типа запуска, вывод PID и код ошибки; при необходимости сделайте два снимка и вставьте их рядом в один рисунок.

В тексте задания для Windows-родителя один раз написано `Lab-02x`; это противоречит описанию Lab-03x и последующим пунктам. В исходниках и отчёте используется `Lab-03x` — этот выбор пояснён в разделе 2.2.

### 2.2 Lab-03a Три варианта CreateProcess

```bat
Lab-03a.exe
```

Первый вызов **должен не создать** процесс: в `lpApplicationName` ошибочно передан путь вместе с `50`. Это часть эксперимента, а не дефект программы. Второй вызов передаёт только изменяемую командную строку, третий — путь в первом параметре и строку ` 50` во втором. Второй и третий дети запускаются до начала ожидания, работают одновременно и печатают разные PID. Родитель выводит номера созданных процессов и дожидается их завершения. **Скриншот 2.2**: вывод родителя, ошибка первого вызова, PID и строки детей.

Пока дети работают, откройте Process Explorer от Microsoft: <https://learn.microsoft.com/en-us/sysinternals/downloads/process-explorer>. В дереве процессов найдите `Lab-03a.exe` и его `Lab-03x.exe`. **Скриншот 2.3**: дерево с родителем и двумя детьми. Выделите родителя, включите нижнюю панель и режим **View → Lower Pane View → Handles**. Найдите открытые дескрипторы типа `Process` и `Thread`, относящиеся к созданным детям. **Скриншот 2.4**: родитель и список дескрипторов до завершения ожидания. Счётчик 50 даёт около 25 секунд на наблюдение; при необходимости повторите запуск.

### 2.3 Пользовательская и локальная ITER_NUM

В **cmd** установите постоянную пользовательскую переменную:

```bat
setx ITER_NUM 12
```

`setx` не меняет уже открытое окно. Закройте его, откройте **новый** x64 Native Tools Command Prompt и введите:

```bat
cd /d "%USERPROFILE%\Desktop\Lab03"
echo %ITER_NUM%
Lab-03x.exe
```

Ожидается `12` и 12 итераций. **Скриншот 2.5**: команда `setx` в старой консоли и проверка `echo %ITER_NUM%` в новой; если это два окна, расположите их рядом или вставьте два снимка под одну подпись.

Теперь в **новой** консоли:

```bat
Lab-03b.exe
```

Ожидаемые количества: первый ребёнок — `12` из постоянной пользовательской переменной; второй — `7` из аргумента; третий — `9` из локальной переменной, которую родитель устанавливает перед его созданием. Дети запускаются до ожидания. **Скриншот 2.6**: все три источника значения и PID.

### 2.4 Lab-03c Перечисление процессов

```bat
Lab-03c.exe
```

Программа использует `CreateToolhelp32Snapshot`, `Process32FirstW`, `Process32NextW` и печатает имя, PID и PPID. **Скриншот 2.7**: видимый фрагмент списка с этими тремя полями.

Во время повторного запуска `Lab-03a.exe` в другом окне **cmd** выполните:

```bat
tasklist /FI "IMAGENAME eq Lab-03x.exe"
taskmgr
```

В Диспетчере задач откройте вкладку **Подробности** и найдите `Lab-03x.exe`, включив столбец PID, если он скрыт. **Скриншот 2.8**: cmd с `tasklist` и Диспетчер задач; PID сопоставьте с выводом родителя. Process Explorer не заменяет эти два отдельно требуемых инструмента.

### 2.5 Lab-03d Поиск взаимно простых чисел через каналы

Сначала проверьте клиента отдельно:

```bat
Lab-03d-client.exe 12 1 31
```

Затем сервер:

```bat
Lab-03d-server.exe 4 12 1 31
```

Ожидаемые числа: `1 5 7 11 13 17 19 23 25 29 31`, всего `11`. Сервер делит 31 число на четыре части: `[1,7]`, `[8,17]`, `[18,24]`, `[25,31]`; остаток `3` добавлен **второму** поддиапазону. Каждый ребёнок имеет отдельный анонимный канал, результаты объединяются и сортируются сервером. Сервер выводит M, диапазон, K, число найденных, сами числа и время. **Скриншот 3.1**: полный вывод сервера и результат.

Чтобы успеть увидеть процессы и дескрипторы, включите **только для диагностического запуска** паузу клиентов:

```bat
set LAB03_PAUSE_MS=15000
Lab-03d-server.exe 4 12 1 31
```

Во время паузы в Process Explorer сделайте **скриншот 3.2** дерева `Lab-03d-server.exe` → четыре `Lab-03d-client.exe`. Затем выделите сервер и переключите нижнюю панель в Handles. Для анонимного канала ожидается тип дескриптора **File**, потому что канал обслуживается файловой подсистемой Windows. **Скриншот 3.3**: дескриптор `File` и родительский процесс. После этого отключите паузу и выполните обычный запуск для достоверного времени:

```bat
set LAB03_PAUSE_MS=
Lab-03d-server.exe 4 12 1 31
```

Не выдавайте время диагностического запуска с искусственной паузой за время вычисления.

### 2.6 Передача фразы через STARTUPINFO

```bat
Lab-03-startup-parent.exe
```

Родитель передаёт строку `Hello, my dear child!` через `STARTUPINFO.lpTitle`, **без аргументов, переменной окружения и IPC**. Для допустимого использования `lpTitle` он создаёт ребёнку новую консоль (`CREATE_NEW_CONSOLE`). Дочерняя консоль остаётся открытой 8 секунд для снимка. **Скриншот 4.1**: оба окна, PID родителя и вывод фразы ребёнком. Не заменяйте этот пункт передачей фразы через командную строку.

## 3. Ubuntu Подготовка и компиляция

Откройте терминал **Ubuntu**, скопируйте туда папку Linux с шестью файлами и выполните:

```bash
sudo apt update
sudo apt install -y build-essential
mkdir -p ~/lab03
cd ~/lab03
ls -l
gcc -std=c11 -Wall -Wextra -O2 -o lab03x lab03x.c
gcc -std=c11 -Wall -Wextra -O2 -o lab03a lab03a.c
gcc -std=c11 -Wall -Wextra -O2 -o lab03d-client lab03d-client.c
gcc -std=c11 -Wall -Wextra -O2 -o lab03d-server lab03d-server.c
gcc -std=c11 -Wall -Wextra -O2 -o signals signals.c
ls -l lab03x lab03a lab03d-client lab03d-server signals
```

Команда `mkdir` лишь создаёт каталог; она **не копирует** файлы. До `gcc` убедитесь через `ls -l`, что все `.c` и `lab03_common.h` уже находятся в `~/lab03`. Если общая папка ВМ монтируется в другом месте, скопируйте файлы оттуда обычным файловым менеджером Ubuntu или командой `cp` с вашим фактическим путём. Рабочий каталог при запусках должен оставаться `~/lab03`.

### 3.1 Lab-03x и Lab-03a

В первом терминале:

```bash
cd ~/lab03
./lab03x 3
ITER_NUM=4 ./lab03x
./lab03a
```

Первый ребёнок `lab03a` получает число `20` через аргумент, второй — `18` из `ITER_NUM`, установленной **родителем перед вторым fork**. Оба создаются до ожидания; время работы около 10 и 9 секунд. **Скриншот 5.1**: родитель, PID и строки обоих детей.

Пока `./lab03a` работает, во втором терминале:

```bash
ps -o pid,ppid,stat,cmd -C lab03x
pgrep -a lab03x
```

Подставьте реальный PID ребёнка из вывода `pgrep`:

```bash
cat /proc/ВАШ_PID/status | grep -E '^(Name|Pid|PPid|State):'
tr '\0' '\n' < /proc/ВАШ_PID/environ | grep '^ITER_NUM='
```

Для второго ребёнка `ITER_NUM=18`; первый мог не унаследовать эту локальную установку, потому что создан раньше. **Скриншот 5.2**: `ps` и `/proc/ВАШ_PID/status`, где видны PID и PPID. `ВАШ_PID` — пояснение, а не буквальная часть команды.

Проверка отсутствия обоих источников:

```bash
env -u ITER_NUM ./lab03x
echo $?
```

Ожидается ненулевой статус. Windows-код `0xC0000005` нельзя переносить буквально: POSIX-статус выхода процесса доступен оболочке в диапазоне 0–255, поэтому Linux-версия возвращает `1`.

### 3.2 Анонимные каналы Linux

```bash
cd ~/lab03
./lab03d-client 12 1 31
./lab03d-server 4 12 1 31
```

Ожидаются те же 11 чисел, что в Windows. Сервер создаёт по одному анонимному каналу для каждого ребёнка, запускает всех детей через `fork` и `execl`, затем читает каналы, ожидает каждого через `waitpid` и выводит общее время. **Скриншот 6.1**: M, `[L,R]`, K, поддиапазоны, количество, числа, время.

Для просмотра дескрипторов запустите диагностическую паузу в первом терминале:

```bash
export LAB03_PAUSE_MS=15000
./lab03d-server 4 12 1 31 &
SERVER_PID=$!
echo "Server PID=$SERVER_PID"
```

Сразу во втором терминале, заменив PID на показанный:

```bash
ps -o pid,ppid,stat,cmd -p ВАШ_SERVER_PID --ppid ВАШ_SERVER_PID
ls -l /proc/ВАШ_SERVER_PID/fd
for p in $(pgrep -P ВАШ_SERVER_PID); do echo "Child $p"; ls -l /proc/$p/fd; done
```

Ищите ссылки вида `pipe:[номер]`: в сервере — читающий конец, у ребёнка — стандартный вывод, направленный в записывающий конец. **Скриншот 6.2**: обе стороны канала и PID. После проверки в первом терминале:

```bash
wait "$SERVER_PID"
unset LAB03_PAUSE_MS
./lab03d-server 4 12 1 31
```

Последний запуск даёт время без диагностической паузы.

### 3.3 Сигналы и Ctrl+C

В первом терминале Ubuntu:

```bash
cd ~/lab03
./signals &
PID=$!
echo "PID=$PID"
sleep 1
kill -USR1 "$PID"
sleep 1
kill -USR1 "$PID"
sleep 1
kill -USR2 "$PID"
sleep 1
kill -USR2 "$PID"
sleep 1
kill -INT "$PID"
sleep 1
kill -0 "$PID" && echo 'SIGINT ignored, process is alive'
kill -USR1 "$PID"
sleep 1
kill -TERM "$PID"
wait "$PID"
```

**Скриншот 7.1**: ответы USR1/USR2, подтверждение, что SIGINT не завершил процесс, и TERM. `kill -INT` проверяет тот же сигнал, который обычно посылается сочетанием Ctrl+C, но **не доказывает физическое нажатие Ctrl+C в терминале**.

Поэтому выполните отдельный опыт. Терминал А:

```bash
cd ~/lab03
./signals
```

Запишите напечатанный PID, нажмите **Ctrl+C** в терминале А. Программа должна продолжить ожидать, приглашение оболочки не вернётся. В терминале Б:

```bash
kill -TERM ВАШ_PID
```

После TERM приглашение вернётся в терминале А. **Скриншот 7.2**: оба терминала рядом — Ctrl+C, отсутствие завершения и команда TERM. Используйте реальный PID; не вводите `ВАШ_PID` буквально.
